# HANDOFF — M24 deferred slate (round 42): TONE-DRILL TRAJECTORY freshness window for the chat-coach context — the symmetric mirror of round 41's SOLVED freshness gate onto the still-in-flight half of the IM tone-drill loop. The chat coach now names a prescribed tone-drill trajectory only when the prescribed scenario itself has a fresh evaluated rep within the recency window AND structurally moves on once the scenario stops being practiced even as the user engages with other modes — instead of restating the same months-old trajectory commentary on every reply forever. Pure-context surface, no engine state change, no schema bump, no view changes. New `CoachContextBuilder.toneDrillTrajectoryIsFresh(scenarioLastEvaluatedDate:now:)` pure predicate (reuses the round-41 `toneDrillSolvedRecencyDays` constant); existing TONE-DRILL TRAJECTORY section in `userContext` now gates on the predicate, anchored against the user's whole-history most-recent practice rep.

## Scope

`IMHistorySummary.toneDrillSignal(from:)` qualifies a scenario whenever it sits sub-40% hit-rate over ≥3 evaluated reps. It carries no recency gate on the latest evaluated rep — correct for the recommendation engine (the gap is real, the drill should still be prescribed on the next IM launch) but it means the chat coach reads the same TONE-DRILL TRAJECTORY section on every reply forever after the qualifying read. A user who hit a tone gap in Difficult Conversation eight weeks ago, never returned to that scenario, but has continued practicing Timed reps + Big Moment + other IM scenarios sees the chat coach restate the trajectory of a scenario they've measurably moved on from — exactly the broken-record register round 41 closed on the SOLVED side.

That is the symmetric mirror of the round-41 gap on stage #3 (Intervention) and stage #4 (Adaptation). The future-move note from round 41 called it out explicitly as the next clean symmetric round, with the design and the restraint pin already worked out: "Mirror the round-41 freshness window onto TRAJECTORY: drop the TRAJECTORY section when the latest evaluated rep in the prescribed scenario is past `toneDrillSolvedRecencyDays` from the user's most-recent rep — same anchor, same window, same `Int` constant... Restraint pin: do not drop TRAJECTORY on a scenario the user practiced recently but in a different mode — the cadence anchor is whole-history-most-recent, not scenario-scoped."

Round 42 closes the gap with the LIGHTEST possible surface: a new pure predicate parallel in shape to round 41's `toneDrillSolvedIsFresh`, plus a freshness clause on the existing TRAJECTORY entry condition in `userContext`. Past the recency window, the section drops entirely — the chat coach has no TRAJECTORY context to reference and so the model can no longer re-issue trajectory commentary on a long-stale read even if it wanted to.

Defensive scoping (intentional restraint, same shape as rounds 37–41):

- **Pure context surface, not engine state change.** No engine-level change to `toneDrillSignal`, `toneDrillProgress`, or the recommendation blueprint (the recommendation engine still prescribes the drill on the next IM launch — the gap is real). Round 42 keeps the impact bounded to the chat coach's context block, the same surface rounds 30–41 fan out across, so the new gate is testable in isolation and reversible if real-conversation evidence shows the window as too tight or too generous.
- **Cross-surface constant reuse, not a parallel copy.** Round 42 explicitly reuses `toneDrillSolvedRecencyDays` (the same `Int` constant round 41 introduced) rather than declaring its own parallel `toneDrillTrajectoryRecencyDays`. The two halves of the tone-drill chat-coach surface (TRAJECTORY before the win, SOLVED after the win) share one knob — a future tune of the SOLVED window auto-propagates to TRAJECTORY. Same architectural shape `repeatedPushbackRecencyDays` already has across rounds 38 + 40 on the case-state matrix. The cross-surface symmetry test pins this with a boundary-parity sweep, not a constant-equality assertion (the constant equality is trivially true by direct reuse).
- **Whole-history anchor, not scenario-scoped (round 41 restraint pin honored).** The anchor is `sessions.lazy.map(\.date).max()` over ALL sessions regardless of mode — Timed, Big Moment, a different IM scenario, all advance the anchor. A user actively practicing OTHER modes but not the prescribed IM scenario has measurably "moved on" from that particular drill, and the chat coach should follow them. A user who's stopped practicing entirely sees both halves of the delta stay close (the prescribed-scenario rep IS the most-recent rep) and the trajectory still fires when they return — the gate is about "the user moved on," not "the user disengaged."
- **Inclusive 14-day boundary.** A scenario rep at exactly 14 days before the anchor still surfaces; a rep 14 days + 1 second before drops. Same shape as round 41's identical recency-pin contract. Pinned by both halves of the boundary (`predicateFiresAtExactRecencyBoundary` + `predicateDropsJustBeyondRecencyBoundary` + a structural userContext boundary test that pins both halves end-to-end), so a future tune of the constant doesn't silently drift the boundary by a day on one half.
- **Defensive negative-elapsed guard.** An anchor (`now`) that pre-dates `scenarioLastEvaluatedDate` is a bad anchor; the predicate refuses to fire rather than returning true on a mathematically-fresh-but-impossible state. Pinned by `predicateDropsWhenAnchorPredatesScenarioLastEvaluatedDate` so a future caller that passes a stale `now` doesn't silently re-surface a dropped trajectory. Identical defensive shape to round 41's `predicateDropsWhenNowPredatesLastEvaluatedDate`.
- **Per-scenario gate, not a global TRAJECTORY-off switch.** The freshness gate applies to the single qualifying scenario `toneDrillSignal(from:)` returns (the worst-hit-rate-first reducer per the existing sort). A fresh TRAJECTORY in scenario A (the prescribed sub-40% scenario the user IS still practicing) and a fresh SOLVED in scenario B (a different scenario the user closed recently) can — and should — both surface, exactly as round 13 designed and round 41 preserved. The gate ONLY drops the TRAJECTORY line when the prescribed scenario itself is stale; it never drops a fresh SOLVED in another scenario, and it never blocks a fresh TRAJECTORY just because some other scenario is stale.
