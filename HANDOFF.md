## What shipped

### Track 1 — `PostRepCoachNoteUserPromptAnchoringTests` suite (`NoumTests/NoumTests.swift`)

Twelve new `@Test` methods inside a new `struct PostRepCoachNoteUserPromptAnchoringTests` suite, slotted immediately after the existing `PostRepCoachNoteJustFinishedRepAnchoringTests` suite (the round-43 deterministic-path anchoring tests) and immediately before `PostRepCoachNoteToneResolvedTests`. Four private fixture helpers — `imSession(id:scenario:targetTone:actualTone:daysOffset:)`, `nonIMSession(daysOffset:)`, `slippingScenarioSessions(scenario:targetTone:offBrandTone:earliestDayOffset:)`, `crossingScenarioSessions(scenario:targetTone:offBrandTone:onBrandTone:crossingRepId:earliestDayOffset:)` — declared verbatim from round 43 so the new suite is self-contained. One private `makeInput(justFinished:allSessions:score:)` factory threads the round-43 helper into the AI-path input — the single wire that locks both surfaces to the same anchoring contract.

- **AI prompt — non-IM reps drop the IM tone-drill clauses (3 tests):**
  - `userPromptOmitsIMTrajectoryClauseForNonIMReps` — Timed rep just-finished + scenario B has a 4-rep below-bar slip → AI prompt omits the `"tone-match"` MOMENTUM clause AND never names scenario B. Helper returns `.empty` for non-IM, so `userPrompt` has nothing to render.
  - `userPromptOmitsIMResolvedClauseForNonIMReps` — Timed rep just-finished + a crossing in scenario B → no `"SOLVED this rep"` clause.
  - `userPromptOmitsIMClausesForLegacyIMRepsWithoutDetails` — defensive: `mode == .imConversation` with `imConversationDetails == nil` → helper returns `.empty` → no clauses.
- **AI prompt — happy-path clauses name the just-finished rep's titles (2 tests):**
  - `userPromptIncludesTrajectoryClauseNamingJustFinishedRepsScenario` — recovering trajectory in scenario A → prompt contains scenario A's title in the `"tone-match"` clause.
  - `userPromptTrajectoryClauseNamesJustFinishedRepsTone` — prompt contains the exact `"\(tone) tone in \(scenario)"` substring with both anchored on the just-finished rep.
- **AI prompt — defensive gating (2 tests):**
  - `userPromptOmitsTrajectoryClauseOnStalledDirection` — stalled progress with valid titles → no `"tone-match"` clause (mirrors deterministic-path stalled fall-through).
  - `userPromptOmitsTrajectoryClauseWhenScenarioTitleIsNil` — defensive nullability guard on the prompt's `let scenario =` / `let tone =` unwraps.
- **AI prompt — cross-rep cold-open contracts (the round-44 core, 3 tests):**
  - `userPromptNeverNamesAnotherScenarioWhenJustFinishedRepIsThin` — end-to-end pin: just-finished rep in scenario A (Networking, thin) + scenario B has a fresh 4-rep below-bar slip. The AI prompt MUST NOT name scenario B's title anywhere; the helper returns nil progress for scenario A's thin history, so no `"tone-match"` clause fires either. Symmetric companion to round-43's `deterministicNoteNeverNamesAnotherScenarioWhenJustFinishedRepIsThin`.
  - `userPromptSolvedClauseNamesJustFinishedScenarioOnly` — crossing rep IS the just-finished rep → SOLVED clause fires and names scenario A's title only, even though other scenarios sit in the user's history.
  - `userPromptNeverNamesAnotherScenarioOnSolvedCrossSurfaceContract` — SOLVED-branch cross-rep cold-open pin: just-finished rep is sub-bar in scenario A; scenario B had a prior crossing rep. The AI prompt's SOLVED clause must not name scenario B's old crossing. Symmetric companion to round-43's `deterministicNoteHeadlinesResolvedWinOnlyForJustFinishedRepsScenario`.
- **AI prompt — defensive SOLVED gate (1 test):**
  - `userPromptOmitsSolvedClauseWhenResolvedIsNil` — a sub-bar rep in scenario A with no crossing → resolved is nil → no `"SOLVED this rep"` clause.
- **Cross-surface contract — both paths name the same scenario (1 test):**
  - `userPromptAndDeterministicNoteNameSameJustFinishedRepsScenario` — calls BOTH `userPrompt(from:)` AND `deterministicNote(input:)` on the same recovering-A-and-slipping-B fixture and asserts BOTH name scenario A AND NEITHER names scenario B. The single test that locks the two surfaces in lockstep — a future helper regression OR a future surface-level regression on either path trips this test.
