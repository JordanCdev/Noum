## Scope

Round 41 closed the freshness gap on the TONE-DRILL SOLVED surface — a once-resolved win no longer parrots itself into the chat-coach context for months after the crossing. But the same shape gap was structurally present on the TRAJECTORY surface: `IMHistorySummary.toneDrillSignal(from:)` fires whenever a scenario clears the evidence bar (≥3 evaluated reps) and the hit rate is sub-40%, with NO recency gate on the latest evaluated rep. A scenario the user practiced 60+ days ago, never returned to, and is still below the bar would surface a TONE-DRILL TRAJECTORY line on every chat reply forever — the same "beating a dead horse" register round 41 closed on the SOLVED side.

That was named as future move #21 from round 41 ("Mirror the TONE-DRILL SOLVED freshness window onto the TONE-DRILL TRAJECTORY surface for stale ACTIVE drills") and round 42 lands it. The recommendation engine still prescribes the drill on the next IM launch (the gap is real — the user has not closed it). The freshness gate is ONLY on the chat-coach context surface; past the window, the chat coach doesn't re-issue the trajectory commentary on a long-stale read, and the coach naturally moves on to a scenario the user is actually practicing.

Round 42 closes the gap with the same LIGHTEST possible surface as round 41: a new pure primitive on `IMHistorySummary` returning the latest evaluated rep date for a scenario, a new pure predicate on `CoachContextBuilder` that compares that date against the user's most-recent rep, and a two-clause additive gate on the existing `if let toneSignal = IMHistorySummary.toneDrillSignal(from: sessions)` block in `userContext`. Past the recency window, the section drops entirely — the chat coach has no TRAJECTORY context to reference and so the model can no longer narrate a stale drill even if it wanted to.

Defensive scoping (intentional restraint, same shape as round 41):

- **Pure context surface, not engine state change.** No engine-level change to `toneDrillSignal` or the recommendation blueprint (the recommendation engine still prescribes the drill — the prescription-on-real-gap contract is preserved). Round 42 keeps the impact bounded to the chat coach's context block, the same surface rounds 30–41 fan out across, so the new gate is testable in isolation and reversible if real-conversation evidence shows the window as too tight or too generous.
- **Recency-anchored against the user's own cadence, not wall-clock.** The anchor is `sessions.lazy.map(\.date).max()` — the user's most-recent practice rep across all history, not `Date()`. This makes the predicate pure and intrinsically test-stable (tests construct sessions with known dates and never depend on the system clock), and it reads as the semantically right thing: "fresh relative to the user's cadence." A user actively practicing other scenarios deserves to see the trajectory named for longer than a user who hasn't practiced at all in a month.
- **Per-scenario gate, not a global TRAJECTORY-off switch.** The freshness anchor is the LATEST evaluated rep in the prescribed scenario (`signal.scenario`). `toneDrillSignal(from:)` picks the worst-hit-rate scenario, so the prescribed scenario can differ from the user's most-recent rep's scenario. The gate compares the PRESCRIBED scenario's latest evaluated rep against the user's overall most-recent rep — drops the section when the prescribed scenario itself has gone cold, regardless of what else the user is practicing.
- **Same constant as round 41.** `toneDrillSolvedRecencyDays` (= 14) is reused — the chat coach's freshness contract is one number across SOLVED + TRAJECTORY. A future tune of the constant touches both surfaces in lockstep, which is the right semantics; the constant-equality test from round 41 already pins it equal to `repeatedPushbackRecencyDays` (the round-38 case-state matrix window), so all three surfaces (SOLVED, TRAJECTORY, case-state matrix) ramp together.
- **Inclusive 14-day boundary.** A scenario whose latest evaluated rep is exactly 14 days old still surfaces; a scenario 14 days + 1 second old drops. Same shape as rounds 38/39/40/41's identical recency-pin contracts. Pinned by both halves of the boundary (`predicateFiresAtExactRecencyBoundary` + `predicateDropsJustBeyondRecencyBoundary` + a structural userContext boundary test that pins both halves end-to-end), so a future tune of the constant doesn't silently drift the boundary by a day on one half.
- **Defensive negative-elapsed guard.** A `now` that pre-dates the latest evaluated rep is a bad anchor; the predicate refuses to fire rather than returning true on a mathematically-fresh-but-impossible state. Pinned by `predicateDropsWhenNowPredatesLatestEvaluatedRep` so a future caller that passes a stale `now` doesn't silently re-surface a dropped trajectory.
- **Defensive no-evaluated-rep guard.** If the prescribed scenario has no evaluated reps in the session set (the primitive returns nil), the predicate refuses to fire. In practice `toneDrillSignal` already requires `evaluatedCount >= 3`, so the predicate returns non-nil whenever the trajectory section would otherwise fire — but the guard keeps the helper safe to call on any session set.
- **SOLVED + TRAJECTORY layer independently per scenario.** A stale TRAJECTORY in scenario A drops while a fresh SOLVED in scenario B still surfaces, and vice versa. Round 41's per-scenario gate semantics are preserved verbatim — round 42 ADDS a per-scenario gate to its own surface without coupling the two.

## What shipped

### Track 1 — `IMHistorySummary.latestEvaluatedRepDate(from:scenario:)` primitive (`Noum/IMHistorySummary.swift`)

- New `static func latestEvaluatedRepDate(from sessions:scenario:) -> Date?` — pure helper. Filters by `.imConversation` mode + scenario match + non-empty actualTone (mirroring `toneMatchStats`'s filter), returns the max session date. Returns nil when no evaluated rep exists for the scenario.
- Placed at the end of `IMHistorySummary` so it sits as one symmetric primitive alongside `toneMatchStats` (the hit-rate primitive) and `dominantEvaluatedTone` (the target-tone primitive), each one operating on the same per-scenario evaluated-rep population.
- Pinned by FOUR primitive tests (`latestEvaluatedRepDateReturnsMostRecentEvaluatedRep`, `latestEvaluatedRepDateIgnoresOtherScenarios`, `latestEvaluatedRepDateExcludesRepsWithoutActualTone`, `latestEvaluatedRepDateReturnsNilWhenNoEvaluatedReps`).

### Track 2 — `CoachContextBuilder.toneDrillTrajectoryIsFresh(signal:in:now:)` predicate (`Noum/CoachContextBuilder.swift`)

- New `static func toneDrillTrajectoryIsFresh(signal: IMToneDrillSignal, in sessions: [PracticeSession], now: Date) -> Bool` — pure predicate. Looks up `IMHistorySummary.latestEvaluatedRepDate(from: sessions, scenario: signal.scenario)`, guards nil and negative-elapsed, then checks `elapsed <= TimeInterval(toneDrillSolvedRecencyDays * 24 * 60 * 60)` (matches the round-41 `toneDrillSolvedIsFresh` body shape exactly).
- Reuses the round-41 `toneDrillSolvedRecencyDays` constant — no new constant. The chat coach's freshness contract is one number across SOLVED + TRAJECTORY.
- Pinned by SIX predicate tests (`predicateFiresWhenNowEqualsLatestEvaluatedRep`, `predicateFiresWithinTheRecencyWindow`, `predicateFiresAtExactRecencyBoundary`, `predicateDropsJustBeyondRecencyBoundary`, `predicateDropsOutsideRecencyWindow`, `predicateDropsWhenNowPredatesLatestEvaluatedRep`, `predicateDropsWhenScenarioHasNoEvaluatedReps`).

### Track 3 — gate on the existing TONE-DRILL TRAJECTORY block in `userContext` (`Noum/CoachContextBuilder.swift`)
